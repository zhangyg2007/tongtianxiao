### 2.3 迁移期间 main 必须保持可运行

强制规则：

1. **每步独立分支 + squash 合并**，单步不跨天；合并前必须过 `ci_smoke.sh`。
2. **先加后切**：新增路由/新表/新脚本先合入，确认无副作用后再切默认行为。
3. **前端切换用配置开关**：`WORKBENCH_AT_ROOT=true|false`，回滚只改 `.env` 并重启，不回滚代码。
4. **数据库只做 `CREATE ... IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS`**，不做 DROP/RENAME。
5. **不删除任何目录**，legacy 仅加说明文件与 README 标注。
6. 每次合并后在服务器打 tag：`deploy-YYYYMMDD-N`，便于回退部署。

**DDL 方向性写法（要点）**

```sql
CREATE TABLE IF NOT EXISTS core.monitor_subject (
    subject_id BIGSERIAL PRIMARY KEY,
    object_id  BIGINT NOT NULL REFERENCES core.object,
    name       TEXT NOT NULL,
    keywords   TEXT[] NOT NULL DEFAULT '{}',
    scope      TEXT NOT NULL DEFAULT 'company',
    enabled    BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT now(),
    UNIQUE (object_id, name)
);
CREATE INDEX IF NOT EXISTS idx_monitor_kw ON core.monitor_subject USING GIN (keywords);

CREATE TABLE IF NOT EXISTS core.monitor_rule (
    rule_id      BIGSERIAL PRIMARY KEY,
    subject_id   BIGINT NOT NULL REFERENCES core.monitor_subject ON DELETE CASCADE,
    platform     TEXT NOT NULL,                 -- weibo/xhs/douyin/news
    freq_minutes INT NOT NULL DEFAULT 60 CHECK (freq_minutes >= 5),
    window_hours INT NOT NULL DEFAULT 24,
    neg_threshold SMALLINT,
    enabled      BOOLEAN DEFAULT TRUE,
    last_run_at  TIMESTAMPTZ
);
CREATE UNIQUE INDEX IF NOT EXISTS uq_rule_subject_platform
    ON core.monitor_rule (subject_id, platform);

CREATE TABLE IF NOT EXISTS core.article (
    article_id  BIGSERIAL PRIMARY KEY,
    platform    TEXT NOT NULL,
    external_id TEXT NOT NULL,
    url         TEXT NOT NULL,
    title       TEXT, author TEXT, content TEXT,
    published_at TIMESTAMPTZ,
    captured_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    sentiment    SMALLINT,                      -- -100..100
    heat         BIGINT DEFAULT 0,
    source_hash  CHAR(64) NOT NULL,
    UNIQUE (platform, external_id),
    UNIQUE (source_hash)
);
CREATE INDEX IF NOT EXISTS idx_article_time ON core.article (published_at DESC);
CREATE INDEX IF NOT EXISTS idx_article_platform_time ON core.article (platform, published_at DESC);

CREATE TABLE IF NOT EXISTS core.metric_daily (
    metric_id      BIGSERIAL PRIMARY KEY,
    subject_id     BIGINT NOT NULL REFERENCES core.monitor_subject ON DELETE CASCADE,
    stat_date      DATE NOT NULL,
    platform       TEXT NOT NULL DEFAULT 'all',
    article_count  INT NOT NULL DEFAULT 0,
    negative_count INT NOT NULL DEFAULT 0,
    positive_count INT NOT NULL DEFAULT 0,
    heat_sum       BIGINT NOT NULL DEFAULT 0,
    UNIQUE (subject_id, stat_date, platform)
);

-- 可选：证据与舆情原文关联（增量、可空）
ALTER TABLE core.evidence
    ADD COLUMN IF NOT EXISTS article_id BIGINT REFERENCES core.article(article_id);
```

## 六、数据迁移

### 6.1 9 表 → 目标结构

**结论：纯增量 ALTER/CREATE，不重建、不迁移历史数据。** ✅

| 现有对象 | 变更 | 方式 |
|---|---|---|
| `core.object` / `object_alias` | 无 | — |
| `core.task` / `task_step` | 无 | — |
| `core.evidence` | 增加可空 `article_id` | `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` |
| `core.artifact` / `_block` / `_citation` / `_anchor` | 无结构变更；补 `storage_path` 唯一索引（可空） | `CREATE UNIQUE INDEX IF NOT EXISTS` |
| 新增 4 表 | `monitor_subject` / `monitor_rule` / `article` / `metric_daily` | `CREATE TABLE IF NOT EXISTS` |
| 版本表 | `core.schema_migration` | `CREATE TABLE IF NOT EXISTS` |

### 6.2 新增 4 表 DDL 要点

见 S3 的 SQL 片段。关键约束：

- `monitor_subject`：`UNIQUE(object_id, name)`；`keywords` 建 GIN 索引。
- `monitor_rule`：`UNIQUE(subject_id, platform)`；`freq_minutes >= 5` 防止过密采集。
- `article`：`UNIQUE(platform, external_id)` 防重复抓取；`UNIQUE(source_hash)` 防跨平台转载重复；时间倒序索引支撑列表页。
- `metric_daily`：`UNIQUE(subject_id, stat_date, platform)`，聚合任务可幂等重跑。

### 6.4 MySQL 采集库并存规则

| 规则 | 内容 |
|---|---|
| 事实源 | PostgreSQL `core` 是唯一业务事实源 |
| 采集库角色 | MySQL 仅存原始抓取（笔记/评论/账号），只允许采集进程写入 |
| 禁止 | 跨库 JOIN；业务代码直连 MySQL；查询时回表 |
| 归一化 | 采集结果经 `backend/sources/` 转 `core.article` / `core.evidence`，保留 `source_url` + `source_hash` |
| 迁移触发 | MySQL 单表 > 5,000 万行，或需要与证据联合检索时，另立迁移计划 |

### 6.5 迁移脚本规范

| 要求 | 做法 |
|---|---|
| 位置 | `bettafish-main/backend/migrations/NNN_name.sql` + `NNN_name_down.sql` |
| 幂等 | 全部 `IF NOT EXISTS`；版本表记录已执行版本，重复执行跳过 |
| 事务 | 每个文件 `BEGIN; ... COMMIT;`；失败自动回滚 |
| 执行入口 | `backend/scripts/init_db.sh` 按版本顺序执行，`--dry-run` 仅打印 |
| 回滚 | 同名 `_down.sql`；DROP 前检查表是否为空，非空需 `--force` |
| 记录 | `core.schema_migration(version, applied_at, checksum)` |
