### 3.4 四引擎重复代码：量化与抽基类收益/风险

行级 diff 实测（✅）：

| 文件 | Query vs Media | Query vs Insight |
|---|---|---|
| `nodes/base_node.py` | 100% | 86% |
| `nodes/formatting_node.py` | 100% | 98% |
| `nodes/report_structure_node.py` | **100%（同 hash）** | 99% |
| `nodes/search_node.py` | **100%（同 hash）** | 99% |
| `nodes/summary_node.py` | 99% | 96% |

| `tools/search.py` | 22% | 17% |

- **复制粘贴规模**：节点层 + 工具层约 **1,700–2,000 行**为近乎逐字复制；抽公共基类可减 **1,200–1,500 行**。

- **风险**：三个引擎的 prompt 变量名与 state 字段并不完全一致（Media 的 `state.py` 多 33 行）；强行统一会让 Query/Media 的输出格式回归。
- **建议**：分两步——先抽 `common/llm` + `common/nodes/{base,formatting,report_structure,search}`（零语义风险），再做 `agent.py` 的策略化（中风险，P2）。**不要一次性重构三个 agent**。
