1. `INSIGHT_ENGINE_*` / `MEDIA_ENGINE_*` / `MINDSPIDER_*` / `FORUM_HOST_*` 四组密钥缺失时，各自在什么阶段失败、是否影响主流程、`MEDIA_ENGINE_*` 是否必须配。

## 二、结论摘要

- **主应用 `app.py` 启动与四组密钥无关**：只要 `MindSpider.main` 能导入（当前可以），8080 正常起；实测日志 `ERROR|Traceback` 计数为 0。
- **主流程（Query 采集 → Report 出报告）当前被 `MEDIA_ENGINE` 卡住**，但原因不是缺 key，而是 `aihubmix.com` 在本机**网络不可达**（DNS 只回一个伪造 IPv6，TCP 443 失败）。
- **`MEDIA_ENGINE_*` 在报告链路里是必需环节**：`ReportEngine` 要求 insight / media / query 三个目录都有新增 `.md`，否则 `/api/report/generate` 直接 400。
- **Gemini 完全可以用 DeepSeek/Kimi 替代，只需改 `.env`**：全项目没有任何 Google SDK，全部走 `openai` SDK + `base_url`；MediaEngine 也没有真正向 LLM 发送图片/视频。
- `pytest tests` 实测 **36 passed**。

## 三、逐引擎影响与失败阶段

### 1. INSIGHT_ENGINE_*

**失败阶段：模块导入期（最严厉）**，但触发点是 `KEYWORD_OPTIMIZER_API_KEY`，不是 `INSIGHT_ENGINE_API_KEY`。

- `InsightEngine/tools/keyword_optimizer.py:50-53`：`KeywordOptimizer.__init__` 在无 key 时 `raise ValueError("未找到硅基流动API密钥...")`
- `InsightEngine/tools/keyword_optimizer.py:297`：模块级 `keyword_optimizer = KeywordOptimizer()` → **导入即执行**
- `InsightEngine/tools/__init__.py:12-16`：`from .keyword_optimizer import ...` 必然触发
- `SingleEngineApp/insight_engine_streamlit_app.py:30`：`from InsightEngine import DeepSearchAgent, Settings` → 页面脚本直接崩

实测：`KEYWORD_OPTIMIZER_API_KEY` 填好后 `InsightEngine.agent` 导入 **OK**（上一轮为空时是 FAIL）。

- `SingleEngineApp/insight_engine_streamlit_app.py:99-102`：`INSIGHT_ENGINE_API_KEY` 为空时只 `st.error` + `return`，**不影响导入**，只在真正发起研究时报错。

**8501 能否起来**：能。Streamlit 的 HTTP 根路径与 `/_stcore/health` 都返回 200，脚本级异常只在浏览器会话里显示。已在服务器单独启动 8501 验证：`root=200`、`health=200`、监听 `127.0.0.1:8501`。

> 附：`KEYWORD_OPTIMIZER_BASE_URL` 当前为空 → `OpenAI(base_url="")` 构造不报错，调用时失败，但 `keyword_optimizer.py:116-142` 有 `_fallback_keyword_extraction` 兜底，**只降关键词质量，不中断流程**。

### 2. MEDIA_ENGINE_*

**失败阶段：类初始化期（Agent 构造时）**。

- `MediaEngine/llms/base.py:36-40`：`if not api_key: raise ValueError("Media Engine LLM API key is required.")`
- `MediaEngine/agent.py:57-63`：`_initialize_llm()` 依次取 `MEDIA_ENGINE_*` → 回退 `MINDSPIDER_*`
- `SingleEngineApp/media_engine_streamlit_app.py:99-103`：`MEDIA_ENGINE_API_KEY` 为空 → `st.error` + `return`

**搜索工具分支**（当前 `SEARCH_TOOL_TYPE=AnspireAPI`）：
- `MediaEngine/agent.py:42`：`DeepSearchAgent` 硬编码 `BochaMultimodalSearch`
- `MediaEngine/agent.py:449`：`AnspireSearchAgent` 用 `AnspireAISearch(api_key=ANSPIRE_API_KEY)`
- 当前走 Anspire 分支，`ANSPIRE_API_KEY` 已填 → **不需要 Bocha key**（`BOCHA_WEB_SEARCH_API_KEY` 为空不影响）

**是否影响主报告：影响。** 见第四节。

### 3. MINDSPIDER_*

**失败阶段：方法调用期**，且不影响 Query→Report 主流程。

- `MindSpider/main.py:47-68`：`check_config()` 校验 `DB_*` + `MINDSPIDER_API_KEY/BASE_URL/MODEL_NAME`，但只被 `run()` 系列调用
- `MindSpider/main.py:139-193`：`initialize_database()` 只建表，不校验 LLM key
- `app.py:281-285`：启动时只调用 `spider.initialize_database()`，不跑爬虫
- `MindSpider/BroadTopicExtraction/topic_extractor.py:13`：真正用 key 的地方

结论：MindSpider 负责**话题发现 + 多平台内容抓取**（独立写库），`QueryEngine` 是另一套搜索采集。缺 key 只影响爬虫工作流，不影响 Query/Report。

### 4. FORUM_HOST_*

**失败阶段：调用期，且异常被吞掉**。

- `ForumEngine/llm_host.py:41-44`：`ForumHost.__init__` 无 key 时 `raise ValueError`
- `ForumEngine/llm_host.py:254-262`：`get_forum_host()` 懒加载 → 调用时才构造
- `ForumEngine/monitor.py:17-22`：`HOST_AVAILABLE` 只取决于 import 是否成功（当前成功）
- `ForumEngine/monitor.py:524-559`：`_trigger_host_speech()` 整体 `try/except`，缺 key 只打日志

**是否被主报告调用**：报告只检查 `logs/forum.log` 是否存在（`ReportEngine/agent.py:1650-1653`），不要求主持人发言。`forum.log` 由 `app.py:351-365 init_forum_log()` 启动即创建。所以缺 key = 论坛少了主持人发言，报告仍可生成。

## 四、MEDIA_ENGINE 是否必需

**结论：在标准 Web 报告链路中是必需环节；但"必需"的是它产出的 `.md` 文件，不是 Gemini 本身。**

- `ReportEngine/agent.py:135-169` `check_new_files()`：任一引擎目录无新增 `.md` → `all_have_new=False`
- `ReportEngine/agent.py:1602-1661` `check_input_files()`：`ready = 三目录都有新增 AND forum.log 存在`
- `ReportEngine/flask_interface.py:407-433` `check_engines_ready()`：固定检查 insight / media / query 三目录
- `ReportEngine/flask_interface.py:653-660`：不 ready → **HTTP 400 "输入文件未准备就绪"**

因此：**MEDIA_ENGINE 不能长期留空**（若配了空 key 同理），否则报告接口永远 400。替代方案是把 `MEDIA_ENGINE_*` 指向一个可达的文本模型（DeepSeek），而不是删掉它。

## 五、Gemini → DeepSeek/Kimi 可行性

**结论：可行，纯 `.env` 改动，零代码改动。**

### Gemini 用在哪
- `config.py:49-52`：Media Agent 推荐 `gemini-2.5-pro` / aihubmix
- `config.py:59-62`：Report Agent 推荐 `gemini-2.5-pro` / aihubmix
- `SingleEngineApp/media_engine_streamlit_app.py:61-62`：注释"强制使用 Gemini"，`model_name = settings.MEDIA_ENGINE_MODEL_NAME or "gemini-2.5-pro"`

### 调用方式
全项目 **没有** `google-generativeai` / `google.genai`。`requirements.txt` 只有 `openai>=1.3.0`。
- `MediaEngine/llms/base.py:11` `from openai import OpenAI`；`:36-55` 组装 `OpenAI(api_key=..., base_url=...)`
- `ReportEngine/llms/base.py:12` 同上
- `QueryEngine/llms/base.py:11`、`InsightEngine/llms/base.py:11`、`ForumEngine/llm_host.py:6`、`MindSpider/BroadTopicExtraction/topic_extractor.py:13`、`InsightEngine/tools/keyword_optimizer.py:6` 全部 `openai`

### 是否真的发图像/视频
**否。** `MediaEngine/llms/base.py` 的 `invoke()/stream_invoke()` 只构造 `[{role:system},{role:user}]` 纯文本 messages，没有 `image_url` / `inline_data` / `Part.from_data` / `files.upload`。
"多模态"来自**搜索 API 返回的结构化卡片**（Bocha/Anspire 返回图文摘要，被拼成文本），不是让 LLM 看图。→ 纯文本模型替代**无功能损失**。

### 改动清单
- **配置级（全部）**：`MEDIA_ENGINE_BASE_URL` / `MODEL_NAME` / `API_KEY`。例：`https://api.deepseek.com` + `deepseek-chat`（或 `deepseek-flash`）。
- **代码级：无。**
- 反向：若想继续用 Gemini，只需换一个**可达**的 OpenAI 兼容中转。

### 各引擎协议一致性
全部 OpenAI 兼容，混用无协议障碍：

| 引擎 | Base URL | 协议 |
|---|---|---|
| Insight | api.moonshot.cn/v1 | OpenAI 兼容 |
| Media | aihubmix.com/v1 | OpenAI 兼容 |
| Query / Report / MindSpider / Forum | api.deepseek.com | OpenAI 兼容 |
| Keyword Optimizer | 空 | OpenAI 兼容 |

## 七、必须补 vs 可长期空着

**必须补（否则功能不可用）**
- `MEDIA_ENGINE_*`：三项都要，且 base_url 必须换成**可达**地址（当前 aihubmix 不通）。建议 DeepSeek。
- `QUERY_ENGINE_*` / `REPORT_ENGINE_*`：主链路必需（已填，DeepSeek）。
- `INSIGHT_ENGINE_*`：主链路必需（已填，Moonshot `kimi-k3` 有效）。
- `ANSPIRE_API_KEY`：`SEARCH_TOOL_TYPE=AnspireAPI` 时 MediaEngine 必需（已填）。

**建议补（影响质量/功能完整性）**
- `KEYWORD_OPTIMIZER_BASE_URL`：当前为空，关键词优化会静默降级。建议填 `https://api.deepseek.com` 并把模型改为 `deepseek-chat`（或填 Moonshot）。
- `MINDSPIDER_*`：只在跑爬虫工作流时需要（已填，DeepSeek）。
- `FORUM_HOST_*`：只影响论坛主持人发言（已填，DeepSeek）。

**可以长期空着**
- `BOCHA_WEB_SEARCH_API_KEY`：走 Anspire 分支时不需要。
- `REDIS_DB_PWD`：当前未用 Redis。
- `SENTIMENT_*`：情感分析默认关闭，已解耦。
